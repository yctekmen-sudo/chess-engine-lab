## Search and compatibility

`engine/src/search/search.cpp` reuses `Traversal::node` for MultiPV=1, sharing
root alpha/beta bounds. It excludes optional root claims, evaluates automatic
root terminals first, and retains all hypothetical descendant claims/history.
Exact incumbent re-search/tie refinement supplies the strongest canonical PLAY,
structured score, PV/end and mate distance; cancellation/atomic completed depths
and evaluator quarantine/error invalidation use the existing traversal machinery.
No second minimax, evaluator change, quiescence or new ordering heuristic exists.

The root neither probes nor stores TT entries under the new policy, avoiding
incompatible numeric reuse of ordinary claim-aware root/subtree values. All
descendant caching remains claim-aware with original evaluator/depth/history
verification. Tests explicitly inject an ordinary numeric root claim entry, in
addition to warm hint/certified tables reused between policies in both directions.

`IterativeSearchOptions::single_pv_play_only` is an appended source-level option
defaulting to true. False retains the original independent exact ranking and root
claims; MultiPV>1 always retains that path. Fixed-depth `search()` is unchanged.
M4/M5 assertions run through an explicit legacy-options wrapper, preserving their
exhaustive, independent oracle, full ranking, cancellation and failure coverage.
M7.2 separately compares the new default with the highest-ranked PLAY from the
full exhaustive ranking at every completed depth, with ordering off/on and TT
off/hint/numeric, cold/warm. It covers both colors, opening positions, captures,
both-color promotions, ties, mate races, stalemate/checkmate, 50/75-move boundaries,
actual/hypothetical repetition, canonical PV termination, cancellation and failure.
The new suite is wired into native and shared WASM CTest.

`engine/src/uci/main.cpp` now requests one variation for single-PV instead of
internally ranking up to 256 candidates. MultiPV>1 retains full exact ranking and
legacy claim extensions. Single-PV supplies an adjacent final-score envelope with
per-process search counter, completed depth, completion/cancellation state, exact
bestmove and finite White raw / White-mate / Black-mate structured score. It never
emits a single-PV root-claim recommendation or invents cp calibration. See the
[wire grammar and safety policy](../controller/README.md#m72-single-pv-final-scores-and-controller-claims).

`controller/src/final-score.ts` validates that contract and uses authoritative
`FideRules` history to prefer a legal claim for an unfavorable/tied PLAY, immediate
before canonical intended move. `ManagedEngine` supplies optional `Proposal.finalSearch`
only for verified trusted engines; malformed/conflicting/nonadjacent/mismatched
or stale evidence fails the session, missing evidence never authorizes automatic
claims, and generic UCI behavior remains unchanged. Search counter and current
session/binding prevent a prior search's score being reused even for the same move.
Completed fixed-depth evidence must reach the requested depth. Cancelled fixed-depth
searches require a controller stop for that session before using a retained
completed depth; non-depth searches retain their engine-local cancellation rules.
Before-depth-one fallback/terminal roots
have no new final score. Old trusted claim extensions are still supported.
Library and GUI analysis explicitly suppress new automatic claim arbitration,
retaining PLAY and score without committing moves. `Game.accept` retains independent
claim/legality, session/root and receipt-deadline validation; clocks and persistence
are unchanged. The proposal type only gains optional metadata.

## Final protocol hardening — 2026-10-22

This follow-up stays on `feature/m7.2-single-pv-search` and changes only
`controller/src/engine.ts`, `controller/test/mock.mjs`,
`controller/test/m7.2-final-score.test.mjs`, `controller/README.md` and this report.
All earlier working-tree changes and the user-provided `m7.2-review.patch` are
preserved. The results above describe the initial M7.2 delivery; the checks below
describe this hardening pass.

The fixed-depth validation now rejects a trusted `status cancelled` envelope
unless the active session's existing `a.evidence.stopRequested` is true. It
rejects unexpected cancellation even when the reported depth equals the requested
depth and when analysis disables claim arbitration. The check runs after envelope
parsing and before any automatic root draw claim. A `status completed` fixed-depth
envelope must still equal the requested depth, and the existing parser still
rejects invalid/oversized depths, malformed scores and stale counters.

The pure parser in `controller/src/final-score.ts` was reviewed and remains
unchanged: stop authorization belongs to the active session, not to the wire
format. No new production state, proposal fields or public interfaces were added.
Movetime, live-clock and infinite requests bypass this fixed-depth-only rule;
generic UCI engines continue to treat these extensions as nonauthoritative.
Search implementation, root claim architecture, evaluator/ABI, TT/MultiPV, clocks
and experiment persistence are unchanged by this follow-up.

Deterministic fixtures can complete at the requested depth, report unsolicited
cancellation, or withhold their result until an actual `stop` command arrives.
Stop tests react to the fixture's `info string fixture waiting for stop` message,
without sleeps, elapsed-time thresholds or racing a search timer. Tests cover:

- Accepted exact-depth completion and rejected shallow `completed` evidence.
- Rejected unsolicited `cancelled` evidence at shallow and equal depth, for play
  and analysis, with no committed move or automatic claim.
- Controller-requested stops retaining a depth-one exact score during a requested
  depth-three search, with independently accepted claims for both colors.
- A prior session's genuine stop, and an idle `stop()`, failing to authorize a
  subsequent search's unsolicited cancellation.
- Explicitly unevaluated before-depth-one fallback with no `finalSearch`, no
  exact reported statistics and no score-based claim despite current eligibility.
- Unchanged engine-local `completed` and `cancelled` results for movetime, clock
  and infinite limits without a controller stop, plus unchanged generic engines.

The earlier arbitration matrix still covers cancelled scores using movetime,
where engine-local cancellation is valid, while the new fixed-depth cases enforce
the tightened policy. No assertion was removed to conceal a failure.
