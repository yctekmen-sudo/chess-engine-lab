## 2. Native C++ UCI executable — implement only approved M6

- Add a **native-only** CMake executable linked to existing Core, Evaluation and Search; do not introduce Node/browser/process dependencies into `chess_core`, evaluator host or `chess_search`. Preserve M2 ABI and M3–M5 APIs. Ensure executable runs under native Debug/Release/Profile and existing native material evaluator packaging.
- Implement `uci` handshake, truthful advertised `option`s, asynchronous `isready`, `setoption` with validated idle-only changes, `ucinewgame`, `position startpos|fen moves`, `go depth|movetime|infinite|clock`, `stop` and `quit`. Reject unsupported control semantics with explicit diagnostics; no silent bogus `searchmoves`/ponder/nodes/mate support. Robust token and duration limits.
- Keep stdin command loop responsive while exactly one C++ worker calls synchronous `iterative_search`. Give each worker a fresh CancellationSource. Handle `stop`, EOF, `quit`, changes to position/config, repeated commands and exceptions deterministically; cancel and join before replacement or TT clear/resize and evaluator replacement. No active worker/TT/evaluator overlap. Proven progress events only after M4 depth commits; no partial result publication.
- Preserve complete `GameHistory` on `position startpos moves`, incomplete on `position fen ... moves`; reconstruct legal history exactly, including actual fullmove/halfmove clock and normalized EP. Invalid commands must not partially overwrite previous valid position. `ucinewgame` may retain M5 table; numeric reuse remains guarded by exact context, evaluator fingerprint, policy and explicit certification. After EVALUATOR_FAILED/SEARCH_ERROR, table owner clears only attached TT **after worker return**.
- Emit legal, canonical `bestmove` once per successful resolved search, `0000` only for terminal/no legal continuation. Emit final-only adjacent `info string chesslab decision claim_draw` or `info string chesslab decision claim_draw_with_intended_move <uci>` before standard `bestmove <best-play>`. For a claim, find **strongest evaluated legal PLAY** at completed depth even if displayed MultiPV=1 (use sufficiently broad internal exact ranking). On cancellation before depth one output an expressly unevaluated legal fallback. Intended move is never actually applied. On evaluator/search failure do **not** issue a fabricated success `bestmove`; terminate/mark unhealthy with clear error diagnostics.
- UCI `info` may show completed depth, nodes, elapsed, canonical legal PV/MultiPV, valid mate scores with correct side-to-move orientation and move count. **Never** emit made-up `score cp` for arbitrary M2 finite scores; expose raw tagged diagnostic until a real mapping exists. `go infinite` must wait for `stop` before `bestmove`, even at engine depth-64 cap; `movetime`/remaining-clock mode uses a bounded documented monotonic *adapter-local* stop scheduler for stand-alone UCI clients, while the M6 controller independently enforces its own game/search deadlines.
- Tests launch real binary with pipes, cover concurrency/races, `isready` under load, `stop`, a no-completed-depth fallback, mate/terminal, draw extension + different strongest PLAY, raw score honesty, evaluator error isolation, config replacement and TT ownership.

## 3. Node.js/TypeScript controller library — authoritative and engine-independent

- Pin a compatible Node/TypeScript/chess.js release and dependencies with lockfile; record license inventory. Keep controller offline, no C++ native binding or required HTTP/WebSocket/React server. Use a typed async library and a thin CLI; do not duplicate adjudication in CLI.
- Implement managed external-UCI subprocess state machine: handshake `uciok`/`readyok` timeouts, real option declaration/effective setting, one `go`/`bestmove` in flight, serial command writes, CRLF and split-line parsing, bounded stdout/stderr, stop grace/kill, worker crashes, duplicate/malformed/late messages and disconnect cleanup. Safe argv `spawn` without shell. Engine provenance and extension trust require explicit configuration/hash; `id name` alone never authorizes claims.
- Associate every process/search with controller generation+session id and expected root/history; never pretend UCI carries IDs. Consume old `bestmove` after `stop` before sending new `position`/`go`; if unresolved, discard/replace process. Discard superseded progress and outcomes. Engines only *propose* actions; controller validates and alone applies moves/claims or outcomes. Only exact committed search decisions can be applied; analysis never auto-plays.
- Use chess.js only behind `Rules`; implement an independent complete FIDE adjudicator and canonical history/repetition tracking. Respect checkmate/stalemate/dead-position precedence, fivefold/75 auto, threefold/50 immediate/intended optional claims, legal EP normalization and incomplete history. Cross-validate with C++ fixtures rather than trusting `chess.js.isGameOver()`/`isInsufficientMaterial()`/`isDraw()` as the final authority.
- Implement untimed and Fischer clocks with a controllable monotonic clock; correctly handle accepted receive timestamp, expired deadline, legal move validation, increment, draw claim (no increment), independent stop deadline and no free grace. For flag result, use proven `can_mate/cannot_mate/undetermined`; **never** use a simplistic opposing-material test to assert impossibility or presume ability where not established. An unknown flag adjudication is a labeled `ADJUDICATION_REQUIRED`, not a chess result; make this explicit for unattended matches.
- Distinguish legal chess results, timeout results, technical forfeits, invalid attempts and unresolved adjudication, with configured match policy. Pause interactive tasks after engine failure; unattended run defaults to labeled technical forfeit, or explicit invalid-game alternative. Do not silently restart failed searches, invent moves or assign a fake PGN result.

## 4. Experiments, CLI, manifests and recovery

- Reproducible immutable, seeded color-swapped paired schedules with identical openings and comparable time controls. Default sequential execution. Preserve exact immutable engine executable hashes, M2 identity/parameters where exposed, UCI options, search depth/order/TT, time policy, platform/tool versions, initial FEN/history completeness and result policy. Use explicit `unknown` when third-party data is not provided. Do not compare unrelated evaluator numeric units or claim deterministic elapsed times.
- Versioned local experiment format: immutable manifest/schedule; incremental recoverable finalized game/attempt records with stable IDs and torn-write protection; atomic summary replacement; standards-compatible PGN and sidecar metadata for claims/failures; safe writer locks and explicit stale-lock takeover. All completed games immutable, one official finalized outcome per scheduled game, no duplicate contribution. Resume command verifies identity/schedule, retains old interrupted attempts and starts new attempts for only unfinished scheduled games from original FEN/clock and fresh engine instances. No invisible resumptions or mid-game clock/TT recovery.
- Expose a reusable async `controller/` TypeScript API for engine, game/analysis, match, status, explicit resume and export. CLI must provide runnable headless commands for at least one position analysis, one paired match, inspection/resume, and PGN/result export, using structured config validation and actionable errors. Include sample configs and exact reproduction commands.

## 5. Mandatory tests and integration gates

1. **Preserve baseline:** existing M0–M5 C++ native and Emscripten/Node CTest suites unchanged in semantic behavior; no evaluator ABI changes or new WASM C++ threading requirement. Native CMake builds/test runs Debug/Release/Profile. All added native executable tests run via CTest or documented integration suite.
2. **Native UCI:** full transcript `uci` → `isready` → `position` → `go` → `info` → `stop` → `bestmove`; fast `stop`; `go infinite` at cap; options and bad inputs; terminal `0000`; immediate/intended claims + best PLAY even when displayed MultiPV=1; canonical PV; finite raw score, mate polarity, interrupted/failure behavior; no leaks or hangs. Include simulated delayed blocking evaluator to check command responsiveness where practical.
3. **Controller/UCI adversarial:** mock engines for partial stdout, huge output, malformed/duplicate bestmove, spoofed Chess Lab extension, crashes, `readyok` delay, stop hang, stale progress and session overlap. Show strict barriers and that failed/superseded sessions never mutate authoritative game state.
4. **Rules differential:** compare exact controller legal moves/FEN/repetition/claims and terminal handling against C++ ChessCore using generated and real chess positions including EP king-safety, 3/5 repetitions, 50/75 clocks and claim-announced move unplayed. Explicitly test timeout impossibility/possibility/unknown cases with sound expected proof classes, including misleading low-material positions.
5. **Clocks and matches:** virtual monotonic clock boundary races, increment only after legal move, no grace subsidy, Fischer and untimed. Real native Chess Lab subprocess plus deterministic UCI fixture engine in a complete paired headless match; verify manifest, effective options, chess-only vs forfeit statistics and PGN.
6. **Persistence:** interrupted attempt, torn record, file-lock conflict/stale recovery, repeated resume/idempotence, immutable completed results and pair schedules, missing executable/config mismatch, no generated chess result for technical/unresolved case. Tests bounded and nonflaky; avoid real wall-time sleeps where a controlled clock/fixture suffices.
7. **CI:** add Node install/typecheck/lint/test and native controller integration using the built UCI executable to GitHub Actions; keep current pinned WASM suite passing. Include Linux toolchain/runtime versions, genuine commands and run links. Do not label an unrun platform tested. A downloaded Stockfish or network in CI is **not** required.
